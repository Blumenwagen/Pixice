# Coding workflow additions

Implemented against T3's released `v0.0.46-nightly.20261008.2813` reference (`30cc788975500a8c00d32a50f348174d1ce578d1`). The full upstream license is in `THIRD_PARTY_NOTICES.md`.

- **Task worktrees:** choose Project or Worktree below a new task's composer. Start from local changes or a Git ref, with an optional branch name. Execution, Review, file tabs, and external editor/terminal actions follow that task's checkout. Clean checkouts can be removed; continuing the task recreates them. See [worktree and rewind details](task-worktrees-and-rewind.md).
- **Queued follow-ups:** while a task runs, choose Queue or Steer in the composer. Queued messages retain their model, reasoning, Fast mode, permission mode, and attachments. Edit, reorder, remove, pause, resume, or steer them from the queue. Restarted queues pause for review, and interrupted dispatches require an explicit retry.
- **Rewind and file restore:** completed prompts expose Edit from here when their provider supports native rewind. Inspect the conversation and file changes first, then keep files or restore an eligible exclusive managed worktree. The original prompt returns to the composer below any unsent draft. Selected-file restoration uses the same revision and ownership checks.
- **PR delivery:** open Pull requests from Preview's new-tab chooser or a GitHub PR link. Commit selected files, push, create a draft PR, and inspect linked PRs, checks, comments, reviews, and diffs. Remote mutations require the relevant user action; merge uses the reviewed head commit.
- **PR watching:** the Watch toggle and `pixice_pull_requests` tools start a persisted monitor when requested. Checks, comments, reviews, and new conflicts queue a read-only inspection turn in the same chat. Watches stop on close/merge, archive, task stop, rewind, repeated failures, or repeated comment-only updates. Remote comments never expand the task's authority.
- **HTML replies:** `pixice_html.publish` attaches a self-contained interactive document to a conversation. Replies support JavaScript, CSS, SVG, canvas, local raster images, live theme variables, source inspection, and normal Preview tabs. The isolated document cannot access Pixice, the parent page, project files, storage, or the network. Codex and Claude can publish replies; forked attachments have independent lifetimes.

Desktop browser checks exercise PR delivery and interactive HTML under Pixice's real content security policy. Native provider history, Git changes, queue dispatch, and service authorization are covered by temporary-repository integration tests. Live GitHub writes and native application launching were not exercised during this browser-only development session.

# Pixice Connect implementation handoff

Status: Implemented; automated and Preview verification complete.

This records the implemented multi-host Connect behavior. Implementation, automated checks, and Preview verification are complete. Physical-device and release validation remain deferred.

The Environment dropdown stays available at the Connect root. A new task keeps its origin environment and project, while Run on selects the execution host. Choosing a different host requires an explicit target project and shows that project's path. Once the task starts, its execution host and project do not change. Follow-ups, approvals, questions, interrupts, previews, browser actions, file operations, and Tool actions stay on that host. Saved thread links retain origin host/project, execution host/project, the raw thread ID, and cached labels. Drafts, workspace data, and preview IDs are scoped so identical IDs from different hosts do not collide. An open execution or saved link for a forgotten host is closed or rejected rather than routed to the local host. See [ConnectRoot.jsx](../src/connect/ConnectRoot.jsx:100), [App.jsx](../src/App.jsx:6085), [ConnectRoot.jsx](../src/connect/ConnectRoot.jsx:375), and [execution-storage.js](../src/connect/execution-storage.js:120).

The host setup path distinguishes temporary access from a permanent endpoint. A permanent HTTPS reverse proxy or Tailscale address is entered and probed against the host identity before sharing. Pairing links are single-use and expire after five minutes. Paired devices show their role, project scope, last-seen time, and 30-day expiry, with explicit renewal and revocation. QR data is generated locally in the browser. Connection errors retain host identity and protocol diagnostics instead of silently switching to another host. See [ConnectionsSettings.jsx](../src/connect/ConnectionsSettings.jsx:178) and [pairing-qr.js](../src/connect/pairing-qr.js:1).

The phone path has an installable app shell and can retain unsent drafts, but actions still need a live host. Browser push is separate and opt-in per host and receiving origin. The host sends generic attention or completion notices that carry only an opaque deep-link target. The receiving client verifies the host and subscription before enabling delivery. Real-device install, suspension, network changes, and Web Push delivery remain untested. See [push-pwa.js](../src/connect/push-pwa.js:27) and [push-client.js](../src/connect/push-client.js:120).

Overview uses bounded, concurrent reads across saved hosts. It reports the last successful check, keeps partial failures visible, labels cached data as last known, and does not open a full workspace stream for a cold or unavailable host. Opening a task still requires a current connection. See [ConnectOverview.jsx](../src/connect/ConnectOverview.jsx:90) and [ConnectOverview.jsx](../src/connect/ConnectOverview.jsx:242).

Observer pairing accepts a non-empty project allowlist. The host applies that scope to calls, collections, files, events, and receipts, and does not expose execution, browser control, provider accounts, usage, or Tools to observers. The UI may explain the limit, but the host remains the authority. See [access-policy.mjs](../electron/connect/access-policy.mjs:1).

When a mutating command loses its response, the client keeps its command ID and offers a read-only outcome check. Results are pending, completed, failed, or unknown. Unknown is honest after a restart, expiry, or missing retained outcome. Pixice never replays an uncertain command automatically. Intervention cache writes now require an open client, the same backend instance, the same attention revision, and the latest read sequence. See [application-client.mjs](../electron/connect/application-client.mjs:130) and [recovery-workspace.jsx](../src/connect/recovery-workspace.jsx:1).

File attachments use host-advertised limits and chunked uploads where supported. Each chunk has a hash, a saved upload is tied to its host, device, and project, and a reselected file must match its saved size and hash. Cancel stops the transfer. Resume sends bytes only and leaves the final task submission to an explicit Send. Generated files can be downloaded through a project-authorized, bounded stream. See [transfer-client.js](../src/connect/transfer-client.js:375) and [transfer-client.js](../src/connect/transfer-client.js:580).

The remote browser supports bounded quality modes, zoom with coordinate conversion, adaptive polling, refresh, pause, and stale-frame messaging. A stale image may remain visible, but input is rejected until a fresh frame arrives. See [RemoteBrowserSurface.jsx](../src/connect/RemoteBrowserSurface.jsx:35), [remote-browser-utils.js](../src/connect/remote-browser-utils.js:1), and [remote-browser.mjs](../electron/browser/remote-browser.mjs:65).

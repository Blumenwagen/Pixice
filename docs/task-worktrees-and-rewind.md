# Task worktrees and edit from here

Before starting a Workspace task, choose **Project folder** or **New worktree** above the composer. A worktree has its own branch, checkout and task file scope while remaining attached to the same Pixice project. Start from current files and changes, or from a named Git branch, tag or commit. Automatic branches use `codex/task-…`.

Current-state starts preserve staged, unstaged, deleted and untracked Git files without changing the original checkout or its index. Nested project folders retain their scope; staged sibling changes stay in the original checkout. Ignored files and installed dependencies are not copied. Reference starts initialize submodules. Current-state capture refuses submodule projects until their local state can be preserved reliably.

The task's model permissions, Review, editable files and result snapshots follow its selected checkout. Forks that share a checkout keep that shared location. The worktree badge displays the branch and execution directory. **Remove clean checkout** requires stopped agents, an exclusive checkout and clean files. Ignored files prevent removal except installed `node_modules`. The branch and conversation remain, and continuing recreates the checkout from that branch. Archiving a task retains its checkout.

For supported Codex threads, **Edit from here** beneath a sent prompt previews the conversation and files that would be affected. **Revert and keep changes** rewinds provider history and returns the original prompt and attachments to the composer. An existing draft remains above the restored prompt. **Revert files too** additionally restores the checkpoint's Git files and staging. You can also restore one selected file without rewinding the conversation.

File restore is offered only for an isolated managed worktree. Other threads, archived forks, and agent sessions using the same directory, a child directory or a parent directory prevent restoration. The preview has a revision token; newer edits require a refreshed preview. Rewind and sends share an admission lock, and restoration keeps a recovery snapshot before touching files. External actions and separate provider memory are outside conversation rewind.

Pixice stores managed workspace metadata in its user-data `task-workspaces/workspaces.json`, checkpoint metadata in `thread-history/checkpoints.json`, and durable file snapshots in hidden Git refs under `refs/pixice/task-starts/`. Checkpoints and recovery snapshots currently remain local without automatic retention cleanup. Their metadata includes the original prompt inputs needed to restore an edit.

The implementation follows the released T3 nightly `v0.0.46-nightly.20261008.2813`: its [composer semantics](https://github.com/pingdotgg/t3code/blob/v0.0.46-nightly.20261008.2813/docs/user/composer.md), [checkpoint rollback service](https://github.com/pingdotgg/t3code/blob/v0.0.46-nightly.20261008.2813/apps/server/src/orchestration-v2/CheckpointRollbackService.ts), [restore safety](https://github.com/pingdotgg/t3code/blob/v0.0.46-nightly.20261008.2813/apps/server/src/orchestration-v2/CheckpointRestoreSafety.ts) and [modern Codex revert boundary](https://github.com/pingdotgg/t3code/blob/v0.0.46-nightly.20261008.2813/apps/server/src/provider/CodexThreadRevert.ts).

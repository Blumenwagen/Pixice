# Native Voice companion handoff

Latest follow-up r34/r35 is ready for coordinator review. The companion is now 224 × 240 logical pixels, with a fully transparent surround and no enclosing card. Only the orb and small status/control pills remain. Controls reveal on hover or keyboard focus; mute, approval, error and recovery indicators persist. Native drag areas and mini buttons remain distinct. Playback-blocked now stays latched across peer connection and repeated track events until an explicit successful play retry. A cancelled or superseded playback attempt cannot restore connected state.

This follow-up ran one blocked-playback regression only, including repeated failure, explicit success and cancellation. Twelve other lifecycle tests were skipped. No lifetime suite, full build, auth/Cloud or standalone orb checks were repeated. One presentation-only native capture batch inspected ordinary, focused, muted/approval, blocked playback and Retry End states. It creates no microphone or transport. Actual Tab input revealed the hidden controls and reached Mute, End, Return and Attach in order. All button rectangles fit and do not overlap. PNG inspection found zero alpha at five surrounding edge points. The dedicated sandboxed native renderer owns one microphone, peer, playback element and local/remote WebAudio analysers from the first explicit `api.voice.companion.open(context)`. Main React has no media owner. Attached presentation starts at the main window's lower right and can be dragged. Detach, reattach, main close/hide and main navigation do not reload the media renderer. The separate transparent frameless window stays on top and clamps to display work areas. Wayland gets an explicit unsupported-desktop error rather than a promise Electron cannot keep.

End, companion close and interface Quit destroy the media renderer immediately, then stop the owned Codex session. The existing Quit-interface behavior still keeps the backend helper available. Delayed Start is awaited before stopping the returned session; uncertain Start is reconciled against backend Voice state. Failed Stop retains ownership and prevents another call. Reopening the same pinned context shows recovery-only Retry End controls without capturing audio. Runtime replacement resets end capture. Provider locate/repair/update/logout cannot replace an active Codex Voice runtime.

The public methods are `open`, `state`, `mute`, `end`, `detach`, `attach` and `returnToPixice`. Their state and the discriminated `VoiceCompanionState` event are typed in `src/pixice-api.d.ts`. Renderer configuration contains the pinned context and display names only. Private `voice.context` retrieves saved project/thread labels on the local desktop. The companion preload exposes fixed lifecycle, reporting and owned-transport calls, with no account token, application API, generic IPC or approval-response method. IPC checks exact webContents and main frame. Navigation, new windows and webviews are denied; its private session grants trusted audio capture only.

Approval requests for the pinned Voice session reach the existing approval UI, including Focus sessions. The companion shows a Review approval button, and notification click/Return selects the real Attention view. Voice does not issue approval decisions. The accepted `VoiceOrb` is imported unchanged. Connected transport maps to listening/speaking from actual audio RMS, and mute suppresses mic levels.

## Verification and evidence

- `tests/voice-companion-lifecycle.test.js`: 12 focused tests passed. Covered single-owner reservation, context pinning, duplicate Start, cancellation during discovery and late Start, uncertain Start reconciliation, cleanup failure/retry, unsupported platforms, approval routing, sender/frame rejection, media release and independent mic/speaker RMS. The recovery-only change was then checked with only its one affected test.
- `tests/voice-companion-native.test.js`: 5 focused tests passed. Covered secure window options, trusted audio permissions, navigation denial, main close continuity, cleanup delegation, reload/crash policy, bounds clamping and Wayland fallback.
- Two existing renderer-media lifetime cases passed using `-t 'Renderer media lifetime'`; seven unrelated Cloud/backend cases were skipped. Auth/Cloud broad suites and standalone orb tests were not run.
- The isolated macOS Electron harness passed 15 native checks. See [native-evidence.json](native-evidence.json). It used Chromium's synthetic microphone, fake signalling and a silent fake playback element. It measured one capture, peer and analysis context through main close and repeated detach/reattach. Native checks covered visibility, actual track muting, same webContents, display clamping, End, companion close, Quit and recovery-only controls. The pending-approval case verified the actual destination passed to the main callback without responding to the request.
- [native-attached.png](native-attached.png), [native-detached.png](native-detached.png), [native-approval.png](native-approval.png) and [native-cleanup-retry.png](native-cleanup-retry.png) capture the real companion BrowserWindow. The detached PNG has a transparent corner alpha of zero. Attached, floating, muted/approval and recovery layouts were visually inspected; controls fit without overlap.
- A desktop renderer build passed. See [renderer-build.log](renderer-build.log). Build output stayed in this directory and was removed after verification. Main/backend/native module syntax checks and the scoped Git whitespace check passed. The diff was inspected for accidental edits.

The native harness did not launch the real application service, use a Codex account, send live audio, or prove provider end-to-end SDP compatibility. Physical microphone permission prompts and real speaker autoplay remain untested; the companion has an Enable audio control if autoplay is blocked. Native display/window behavior was verified on macOS, not Windows or X11. Wayland is intentionally unsupported. Backend cleanup cannot be confirmed during an outage; capture still ends immediately, the failed session remains reserved, and the next open offers explicit Retry End. No renderer can start another session until that cleanup succeeds.

Run the harness with the installed Electron binary, unsetting `ELECTRON_RUN_AS_NODE`, and an isolated Vite server on port 5188. `native-harness.mjs` uses private temporary user data and never takes the running Pixice instance lock. `harness.jsx` supplies fake signalling/playback while leaving media capture and WebAudio real, with Chromium's synthetic input device.

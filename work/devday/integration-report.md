## Implemented behavior

### Conversational Voice

Focus and ordinary Codex tasks now have a Voice toolbar button. Opening the dialog checks native support without capturing audio. Start Voice explicitly requests the selected microphone, negotiates WebRTC through the installed Codex app-server, and plays the remote audio. Mute, playback recovery, transcript display, End conversation, Escape, and navigation cleanup are connected.

The implementation uses experimental `thread/realtime/start`, `thread/realtime/listVoices`, `thread/realtime/stop`, and the SDP, started, transcript, error, and closed notifications generated by codex-cli 0.159.2. It sends `outputModality: audio` and `transport: {type: webrtc, sdp}`. The renderer owns media; the host owns thread selection. Failed starts and cancellation hold the session lock through cleanup. Failed Stop retains the lock for an explicit retry. Untagged native closed/error notifications are advisory because this CLI identifies them only by thread, not by realtime session. They cannot terminate a replacement session. Owned WebRTC closure, explicit Stop, failed Start, and runtime disconnection perform cleanup.

The host resumes the actual existing thread with Pixice's dynamic tools and project instructions, then applies its model, effort, working directory, sandbox, and approval settings through `thread/settings/update`. `clientManagedHandoffs: false` leaves delegation with Codex's native backing thread. Focus uses the existing coordinator permission policy. Managed workers cannot open Voice. Approval requests continue through Pixice's existing request handlers.

Native protocol defaults choose the Voice engine and version. The selected coding model governs the backing thread; Pixice does not claim that GPT-6.1 Sol is the audio model. Existing dictation code and the composer markup are unchanged. Voice is a portal overlay. Geometry measurements at a 1440 by 1020 viewport confirm identical chat, composer, and textarea bounds before and after opening it.

### Codex Cloud

Settings has a Codex Cloud page with per-project saved environment IDs, account task listing and pagination, task status, patch inspection, prompt, branch, and attempts. These call real CLI operations through argument arrays without a shell. SIWC credentials are excluded from this process.

Submission first shows the concrete environment, prompt, branch, and attempts. Only Submit Cloud task invokes `codex cloud exec`. Applying requires a reviewed attempt and a second explicit action. The host retains the exact displayed diff bytes in a bounded, single-use, project-bound snapshot for 10 minutes. Apply validates its receipt and feeds those same bytes to Git locally. It does not refetch remote bytes or call `codex cloud apply`. Active project work blocks application, and the project lock prevents new local turns or Voice from racing the patch. Git retains its default path safeguards and fails conflicting patches without enabling partial-hunk rejection.

The installed CLI exposes `exec`, `status`, `list`, `apply`, and `diff`. It has no noninteractive environment discovery command. The supported interactive `codex cloud` interface can browse environments. The page therefore saves exact IDs supplied by the user. No private service endpoint, environment creation, publication, or full environment browser has been invented.

### App-owned Sign in with ChatGPT

Providers settings now has a separate Continue with ChatGPT flow, account profiles, reauthorization, explicit Use for Codex selection, source restoration, sign-out, and an account-management link. Existing Codex OAuth remains its own flow.

The host implements the documented dynamic public-client flow with a stable UUIDv4 host identity, fresh state, nonce, PKCE, an exact HTTP loopback callback, system browser authorization, issued client ID exchange, and signed ID-token verification through OpenAI's JWKS. Returning account verification checks the original registration and subject. Identity alone does not authorize plan usage; the actual granted `chatgpt.tokens.use.direct` scope is required.

Profiles and token material are atomically encrypted through Pixice's existing credential storage with owner-only file permissions. Refresh is serialized and stores rotating refresh tokens together with the access token, scopes, and expiry. Sign-out attempts documented remote refresh-session revocation before clearing local tokens while retaining the account registration. The UI reports confirmed revocation or gives an actionable warning to disconnect Pixice in ChatGPT Settings. IPC, renderer state, application settings, and process arguments contain no tokens.

Selecting a profile while Codex is idle starts the documented `openai_chatgpt_plan` Responses provider with `ACCESS_TOKEN` only in the child environment. Credential-bearing stderr is suppressed for that runtime. Renewal restarts the server while idle and forces thread restoration before inference. Existing model-provider configuration is retained for switching back. Active work and Voice block account switching. Claude is not reconfigured.

The three new capability groups are host-local. They are wired through backend dispatch, the local application contract, preload, and TypeScript declarations. They are absent from paired Connect's remote capability contract. Voice SDP and account events are also absent from remote events.

## Vendor and eligibility limitations

- Native Voice methods and voice discovery are present and responded on this installation. A real microphone conversation and live Focus handoff were not started. Account entitlement and end-to-end media negotiation still need an explicit user session.
- App sign-in currently covers eligible Responses inference. It does not authorize conversational Voice. With the app profile selected, Voice gives a useful instruction to switch to the existing Codex account. Cloud also uses normal CLI authentication independently.
- Model listing is a catalog, not proof of plan entitlement. No real OAuth registration, token refresh against OpenAI, or plan inference was performed. Fixtures exercise those paths locally without vendor effects.
- README states that Pixice has no product license. It cannot claim the open-source eligibility route from its current license. The official cookbook permits personal projects running locally; commercial or hosted distribution requires participation access. The eligibility question is unanswered. No commercial registration, licensing change, or distribution approval is implied by this implementation.
- Cloud environment IDs need user input. New published environment compatibility has not been established by a test submission. The CLI does not expose environment creation or publication, and this UI does not promise them.
- These integrations are local desktop features in this phase. Paired Connect and Claude Voice are not added. Existing Connect, Claude, and dictation implementations remain in place.

## Independent review corrections, 2026-09-30

The existing outcome and thread were retained. Direction 28 was acknowledged again. All three reproduced defects are corrected.

- `chatgpt-auth.mjs` discovers the revocation endpoint from OpenAI's OIDC metadata. It validates the issuer and HTTPS auth origin, forbids redirects, submits the refresh token with the issued client ID, and retries network or 5xx failures once with bounded backoff. Local tokens are cleared even when revocation fails. Public state and Providers UI distinguish confirmed revocation from a warning with a ChatGPT Settings action. A read-only discovery request confirmed the advertised endpoint. No real token was revoked. The exact guidance is [End the renewable session](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions#end-the-renewable-session).
- Sign-in setup, timeout, callback success, and callback error now finish only their owning attempt through `cancelAttempt`. Stale exchange, verification, and browser setup completions cannot cancel a newer sign-in or replace its UI error.
- `codex-voice.mjs` retains the session during failed-start Stop, explicit Stop, and failed cleanup. Ownership and runtime generation guards protect replacements. The renderer shares its pending cleanup promise, waits for late Start responses, and guards callbacks and restart against the old connection. Native terminal notifications lack a session ID in this CLI, so untagged notifications are advisory rather than authority to end a replacement; WebRTC transport failure and negotiation timeout still clean up the owned session.
- Installed CLI help confirms both diff and apply support `--attempt`. The earlier assertion that apply lacked it was incorrect. No documented immutable-attempt or expected-diff-hash guarantee was established. The old hash check plus remote apply therefore did not provide an atomic binding. It has been replaced by application of the validated host-held snapshot through Git, with no remote refetch. The UI shows the selected attempt and explains the snapshot.

Only `tests/devday-review-regressions.test.js` ran for this correction, with 11 passing regressions. They cover revocation success/failure and foreign endpoint rejection, stale OAuth attempt/setup completions, failed-start and failed-Stop locking, replacement protection, late renderer Start and repeated Close, exact reviewed-byte application, project binding and single use, and real Git application/conflict/path safeguards in temporary folders. `git diff --check` passed. No broad suite, build rerun, unchanged UI recapture, live vendor mutation, commit, push, or installation ran. The previous screenshots remain initial integration evidence; they do not show the new warning or snapshot controls.

# Board stewardship

Treat this behaviour being enabled as the user's preference for proactive board upkeep. Do not wait for the user to mention the board. Inspect the project's board when work concerns a backlog, priorities, planned work, deferred follow-ups, or an effort likely to span sessions. Also inspect it at the start of a substantial task when the current thread may correspond to existing tracked work.

When the current thread matches an existing task, attach it rather than creating a duplicate. Move the task to active when execution starts and to done only after the requested outcome is complete. Keep its description current when acceptance details, blockers, or the agreed scope change.

Create a board task when the user asks to defer, revisit, prioritize, or follow up on concrete work. During implementation, capture a newly discovered follow-up when it is clearly outside the current scope and useful enough to resume in a later session. Check for duplicates first. Keep titles short and put acceptance details, blockers, and useful handoff context in the description.

Do not mirror an agent's plan or temporary implementation checklist onto the board. Plans describe the current turn. Board tasks record durable work the user may want to find, prioritize, or resume later. Do not create speculative tasks for every possible improvement.

# Workflow-first automation

Treat Pixice workflows as the default home for repeatable automation. When a request is recurring, scheduled, webhook-driven, or made of stable steps that benefit from a visible audit trail, explicitly assess whether a workflow fits before building a one-off script or handling the steps only in chat.

When the user asks to automate, operationalize, schedule, or reuse a process, prefer creating or updating a Pixice workflow when the available nodes can express it well. Inspect existing workflows before creating a duplicate. Build deterministic work with native action, control-flow, and data nodes. Reserve Pixice Agent nodes for judgment or open-ended synthesis. Attach project Skills through Use Skill nodes instead of copying their instructions into prompts.

Keep the graph readable, test it with a representative input, and leave its canvas open for review. Do not create a durable workflow for a simple one-off task, and do not enable automatic triggers unless the user has asked for the automation to run unattended.
